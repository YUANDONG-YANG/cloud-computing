1. Enhanced Cloud Architecture

Phase 3 extends the Phase 2 static web app with three pillars: event-driven data processing (Azure Function blob trigger), caching (Azure Cache for Redis / Cosmos DB), and authentication/security (Azure Static Web Apps Auth, OAuth, encryption at rest).

Architecture Diagram

Key Architecture Decisions

Event-Driven

Blob trigger fires the cleaning function only when All_Diets.csv is uploaded or modified, eliminating unnecessary computation.

Cache-First

Pre-computed aggregations stored in Redis provide sub-10ms reads. Cosmos DB holds cleaned recipe data for complex queries.

Auth Gate

All dashboard routes are protected. Users must authenticate via email/password or OAuth before accessing any data.

Encrypted

Cosmos DB encrypts all data at rest with AES-256. Passwords are stored as bcrypt hashes, never plaintext.

2. Performance Optimization

2.1 Blob Trigger — Data Cleaning (10 marks)

The Azure Function listens for changes to All_Diets.csv in the nutrition-data Blob Storage container. When the file is uploaded or modified, the function automatically:

  1. Parses the CSV (7,806 rows, 5 diet types)
  2. Removes duplicate entries and rows with missing nutritional values
  3. Normalizes diet type names (lowercase, trim whitespace)
  4. Validates numeric fields (Protein_g, Carbs_g, Fat_g ≥ 0)
  5. Writes cleaned data to Cosmos DB

Blob Trigger Function

    {

      "path": "nutrition-data/All_Diets.csv",

// index.js - Azure Function (BlobTrigger)
const { CosmosClient } = require("@azure/cosmos");
const csv = require("csv-parser");
const { Readable } = require("stream");

module.exports = async function (context, csvBlob) {
  context.log("Blob trigger fired: All_Diets.csv modified");
  context.log(`Blob size: ${csvBlob.length} bytes`);

  const rows = [];
  const stream = Readable.from(csvBlob.toString());

  await new Promise((resolve, reject) => {
    stream
      .pipe(csv())
      .on("data", (row) => {
        // Data cleaning: normalize, validate, deduplicate
        const cleaned = {
          recipe_name: (row.Recipe_name || "").trim(),
          diet_type:   (row.Diet_type || "").toLowerCase().trim(),
          protein_g:   parseFloat(row.Protein_g) || 0,
          carbs_g:     parseFloat(row.Carbs_g) || 0,
          fat_g:       parseFloat(row.Fat_g) || 0,
        };

        // Validate: skip rows with empty names or invalid diet types
        const validDiets = ["dash", "keto", "mediterranean", "paleo", "vegan"];
        if (cleaned.recipe_name && validDiets.includes(cleaned.diet_type)) {
          rows.push(cleaned);
        }
      })
      .on("end", resolve)
      .on("error", reject);
  });

  context.log(`Cleaned ${rows.length} valid recipes from CSV`);

  // Write cleaned data to Cosmos DB
  const client = new CosmosClient(process.env.COSMOS_CONNECTION);
  const container = client.database("nutritionDB").container("recipes");

  for (const row of rows) {
    await container.items.upsert({ ...row, id: row.recipe_name });
  }

  context.log("Cleaned data written to Cosmos DB");
};

2.2 Result Caching — Redis / Cosmos DB (10 marks)

After cleaning, the function pre-computes aggregated results (average macros per diet, recipe counts, totals) and stores them in Azure Cache for Redis. Dashboard reads never re-process the raw CSV — they fetch pre-computed results from cache.

Caching Logic

// cacheResults.js - Pre-compute and cache aggregations
const redis = require("redis");

async function cacheAggregations(cleanedRows) {
  const client = redis.createClient({
    url: process.env.REDIS_CONNECTION_STRING,
    password: process.env.REDIS_KEY,
    tls: { servername: process.env.REDIS_HOST }
  });
  await client.connect();

  // Group by diet type
  const dietGroups = {};
  cleanedRows.forEach(row => {
    if (!dietGroups[row.diet_type]) dietGroups[row.diet_type] = [];
    dietGroups[row.diet_type].push(row);
  });

  // Compute and cache averages per diet
  for (const [diet, recipes] of Object.entries(dietGroups)) {
    const count = recipes.length;
    const avgProtein = recipes.reduce((s, r) => s + r.protein_g, 0) / count;
    const avgCarbs   = recipes.reduce((s, r) => s + r.carbs_g, 0)   / count;
    const avgFat     = recipes.reduce((s, r) => s + r.fat_g, 0)     / count;

    await client.hSet(`diet:${diet}`, {
      count:      count.toString(),
      avgProtein: avgProtein.toFixed(2),
      avgCarbs:   avgCarbs.toFixed(2),
      avgFat:     avgFat.toFixed(2),
    });
  }

  // Cache total recipe count
  await client.set("total_recipes", cleanedRows.length.toString());
  await client.disconnect();
}

module.exports = { cacheAggregations };

3.1 Diet Type Filter (5 marks)

Users can filter recipes by selecting a diet type from a dropdown. The API queries Cosmos DB with a partition key filter, returning only matching recipes.

Filter API Endpoint

// api/recipes/filter.js
const { CosmosClient } = require("@azure/cosmos");

module.exports = async function (context, req) {
  const dietType = req.query.diet || "all";
  const client = new CosmosClient(process.env.COSMOS_CONNECTION);
  const container = client.database("nutritionDB").container("recipes");

  let query;
  if (dietType === "all") {
    query = "SELECT * FROM c";
  } else {
    query = {
      query: "SELECT * FROM c WHERE c.diet_type = @diet",
      parameters: [{ name: "@diet", value: dietType.toLowerCase() }]
    };
  }

  const { resources } = await container.items.query(query).fetchAll();

  context.res = {
    status: 200,
    headers: { "Content-Type": "application/json" },
    body: { count: resources.length, recipes: resources }
  };
};

3.2 Keyword Search (10 marks)

Users can search recipes by keyword (e.g., "chicken", "salad"). The API uses Cosmos DB's CONTAINS function for case-insensitive substring matching on the recipe name.

Search API Endpoint

// api/recipes/search.js
module.exports = async function (context, req) {
  const keyword  = (req.query.q || "").toLowerCase();
  const page     = parseInt(req.query.page) || 1;
  const pageSize = parseInt(req.query.pageSize) || 20;
  const offset   = (page - 1) * pageSize;

  const client = new CosmosClient(process.env.COSMOS_CONNECTION);
  const container = client.database("nutritionDB").container("recipes");

  // Count total matching results
  const countQuery = {
    query: "SELECT VALUE COUNT(1) FROM c WHERE CONTAINS(LOWER(c.recipe_name), @kw)",
    parameters: [{ name: "@kw", value: keyword }]
  };
  const { resources: countResult } = await container.items.query(countQuery).fetchAll();
  const totalCount = countResult[0] || 0;

  // Fetch paginated results
  const dataQuery = {
    query: `SELECT * FROM c WHERE CONTAINS(LOWER(c.recipe_name), @kw)
            ORDER BY c.recipe_name
            OFFSET @offset LIMIT @limit`,
    parameters: [
      { name: "@kw", value: keyword },
      { name: "@offset", value: offset },
      { name: "@limit", value: pageSize }
    ]
  };
  const { resources } = await container.items.query(dataQuery).fetchAll();

  context.res = {
    status: 200,
    body: {
      keyword, page, pageSize,
      totalCount,
      totalPages: Math.ceil(totalCount / pageSize),
      recipes: resources
    }
  };
};

Pagination Component

// Pagination renderer
function renderPagination(currentPage, totalPages) {
  const container = document.getElementById("pagination");
  container.innerHTML = "";

  // Previous button
  const prev = document.createElement("button");
  prev.textContent = "Previous";
  prev.disabled = currentPage === 1;
  prev.onclick = () => loadPage(currentPage - 1);
  container.appendChild(prev);

  // Page numbers (show max 5 around current)
  const start = Math.max(1, currentPage - 2);
  const end   = Math.min(totalPages, currentPage + 2);
  for (let i = start; i <= end; i++) {
    const btn = document.createElement("button");
    btn.textContent = i;
    btn.className = i === currentPage ? "active" : "";
    btn.onclick = () => loadPage(i);
    container.appendChild(btn);
  }

  // Next button
  const next = document.createElement("button");
  next.textContent = "Next";
  next.disabled = currentPage === totalPages;
  next.onclick = () => loadPage(currentPage + 1);
  container.appendChild(next);
}

async function loadPage(page) {
  const q = document.getElementById("search-input").value;
  const res = await fetch(`/api/recipes/search?q=${encodeURIComponent(q)}&page=${page}`);
  const data = await res.json();
  renderRecipeTable(data.recipes);
  renderPagination(data.page, data.totalPages);
}

4. Authentication & Security

4.1 Email / Password Registration & Login (10 marks)

Users register with an email and password. The password is hashed using bcrypt (12 salt rounds) before storage in Cosmos DB. Login verifies the hash. Sessions use signed JWTs with a 24-hour expiry.

Registration Endpoint

// api/auth/register.js
const bcrypt = require("bcryptjs");
const { CosmosClient } = require("@azure/cosmos");

module.exports = async function (context, req) {
  const { email, password, name } = req.body;

  // Validate input
  if (!email || !password || password.length < 8) {
    context.res = { status: 400, body: { error: "Invalid email or password (min 8 chars)" } };
    return;
  }

  const client = new CosmosClient(process.env.COSMOS_CONNECTION);
  const container = client.database("nutritionDB").container("users");

  // Check if user already exists
  const { resources: existing } = await container.items
    .query({ query: "SELECT * FROM c WHERE c.email = @email",
             parameters: [{ name: "@email", value: email }] })
    .fetchAll();

  if (existing.length > 0) {
    context.res = { status: 409, body: { error: "Email already registered" } };
    return;
  }

  // Hash password with bcrypt (12 salt rounds)
  const passwordHash = await bcrypt.hash(password, 12);

  // Store user - NEVER store plaintext password
  await container.items.create({
    id: email,
    email,
    name,
    passwordHash, // bcrypt hash, not plaintext
    createdAt: new Date().toISOString()
  });

  context.res = { status: 201, body: { message: "User registered successfully" } };
};

Login Endpoint

// api/auth/login.js
const bcrypt = require("bcryptjs");
const jwt    = require("jsonwebtoken");

module.exports = async function (context, req) {
  const { email, password } = req.body;

  const client = new CosmosClient(process.env.COSMOS_CONNECTION);
  const container = client.database("nutritionDB").container("users");

  const { resources } = await container.items
    .query({ query: "SELECT * FROM c WHERE c.email = @email",
             parameters: [{ name: "@email", value: email }] })
    .fetchAll();

  if (resources.length === 0) {
    context.res = { status: 401, body: { error: "Invalid credentials" } };
    return;
  }

  const user = resources[0];

  // Verify password against stored bcrypt hash
  const valid = await bcrypt.compare(password, user.passwordHash);
  if (!valid) {
    context.res = { status: 401, body: { error: "Invalid credentials" } };
    return;
  }

  // Generate JWT token (24h expiry)
  const token = jwt.sign(
    { userId: user.id, email: user.email, name: user.name },
    process.env.JWT_SECRET,
    { expiresIn: "24h" }
  );

  context.res = {
    status: 200,
    body: { token, user: { email: user.email, name: user.name } }
  };
};

4.2 OAuth Integration — Google & GitHub (10 marks)

Users can sign in with their Google or GitHub account via OAuth 2.0. Azure Static Web Apps provides built-in OAuth support, or the app can implement a custom OAuth flow with redirect handling.

OAuth Flow

OAuth Callback Handler

// api/auth/callback/google.js
const { OAuth2Client } = require("google-auth-library");
const jwt = require("jsonwebtoken");

const googleClient = new OAuth2Client(
  process.env.GOOGLE_CLIENT_ID,
  process.env.GOOGLE_CLIENT_SECRET,
  process.env.GOOGLE_REDIRECT_URI
);

module.exports = async function (context, req) {
  const { code } = req.query;

  // Exchange authorization code for tokens
  const { tokens } = await googleClient.getToken(code);
  const ticket = await googleClient.verifyIdToken({
    idToken: tokens.id_token,
    audience: process.env.GOOGLE_CLIENT_ID
  });

  const { email, name, picture } = ticket.getPayload();

  // Create or update user in Cosmos DB
  const client = new CosmosClient(process.env.COSMOS_CONNECTION);
  const container = client.database("nutritionDB").container("users");

  await container.items.upsert({
    id: email,
    email,
    name,
    picture,
    provider: "google",
    lastLogin: new Date().toISOString()
  });

  // Issue JWT session token
  const token = jwt.sign(
    { userId: email, email, name, provider: "google" },
    process.env.JWT_SECRET,
    { expiresIn: "24h" }
  );

  // Redirect to dashboard with token
  context.res = {
    status: 302,
    headers: {
      Location: `/?token=${token}`,
      "Set-Cookie": `auth_token=${token}; HttpOnly; Secure; SameSite=Strict; Max-Age=86400`
    }
  };
};

4.4 Auth Gate — Dashboard Access Control (10 marks)

The dashboard is protected by an authentication gate. Unauthenticated users are redirected to the login page. Authenticated users see their name and a logout button in the top-right corner of the dashboard header.

Auth Middleware

// middleware/auth.js
const jwt = require("jsonwebtoken");

function authMiddleware(context, req) {
  const token = req.headers["authorization"]?.replace("Bearer ", "")
             || req.cookies?.auth_token;

  if (!token) {
    context.res = { status: 401, body: { error: "Authentication required" } };
    return null;
  }

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    return decoded; // { userId, email, name, provider }
  } catch (err) {
    context.res = { status: 401, body: { error: "Invalid or expired token" } };
    return null;
  }
}

module.exports = { authMiddleware };

Frontend Auth Gate

// auth-gate.js - Redirect to login if not authenticated
(function checkAuth() {
  const token = localStorage.getItem("auth_token")
             || getCookie("auth_token");

  if (!token) {
    window.location.href = "/login";
    return;
  }

  // Decode JWT to get user info (non-sensitive display only)
  try {
    const payload = JSON.parse(atob(token.split(".")[1]));
    if (payload.exp * 1000 < Date.now()) {
      localStorage.removeItem("auth_token");
      window.location.href = "/login";
      return;
    }
    // Show user name and logout button
    document.getElementById("user-name").textContent = payload.name;
    document.getElementById("auth-section").style.display = "flex";
  } catch (e) {
    window.location.href = "/login";
  }
})();

// Logout handler
document.getElementById("logout-btn").addEventListener("click", () => {
  localStorage.removeItem("auth_token");
  document.cookie = "auth_token=; Max-Age=0; path=/";
  window.location.href = "/login";
});

// api/dashboard/stats.js - Read from Redis cache
const redis = require("redis");

module.exports = async function (context, req) {
  const client = redis.createClient({
    url: process.env.REDIS_CONNECTION_STRING,
    password: process.env.REDIS_KEY,
    tls: { servername: process.env.REDIS_HOST }
  });
  await client.connect();

  const diets = ["dash", "keto", "mediterranean", "paleo", "vegan"];
  const stats = {};

  for (const diet of diets) {
    const data = await client.hGetAll(`diet:${diet}`);
    stats[diet] = {
      count:      parseInt(data.count),
      avgProtein: parseFloat(data.avgProtein),
      avgCarbs:   parseFloat(data.avgCarbs),
      avgFat:     parseFloat(data.avgFat),
    };
  }

  const totalRecipes = await client.get("total_recipes");
  await client.disconnect();

  context.res = {
    status: 200,
    body: { totalRecipes: parseInt(totalRecipes), diets: stats }
  };

6.2 Search / Filter API with Pagination

// api/recipes/index.js - Combined filter + search + pagination
const { CosmosClient } = require("@azure/cosmos");
const { authMiddleware } = require("../middleware/auth");

module.exports = async function (context, req) {
  // Verify authentication
  const user = authMiddleware(context, req);
  if (!user) return; // 401 already set by middleware

  const diet     = req.query.diet || "all";
  const keyword  = (req.query.q || "").toLowerCase();
  const page     = Math.max(1, parseInt(req.query.page) || 1);
  const pageSize = Math.min(50, parseInt(req.query.pageSize) || 20);
  const offset   = (page - 1) * pageSize;

  const client = new CosmosClient(process.env.COSMOS_CONNECTION);
  const container = client.database("nutritionDB").container("recipes");

  // Build dynamic query
  let conditions = [];
  let params = [];

  if (diet !== "all") {
    conditions.push("c.diet_type = @diet");
    params.push({ name: "@diet", value: diet });
  }
  if (keyword) {
    conditions.push("CONTAINS(LOWER(c.recipe_name), @kw)");
    params.push({ name: "@kw", value: keyword });
  }

  const where = conditions.length ? `WHERE ${conditions.join(" AND ")}` : "";

  // Get count
  const countQ = { query: `SELECT VALUE COUNT(1) FROM c ${where}`, parameters: params };
  const { resources: [totalCount] } = await container.items.query(countQ).fetchAll();

  // Get page
  const dataQ = {
    query: `SELECT * FROM c ${where} ORDER BY c.recipe_name OFFSET @off LIMIT @lim`,
    parameters: [...params,
      { name: "@off", value: offset },
      { name: "@lim", value: pageSize }
    ]
  };
  const { resources } = await container.items.query(dataQ).fetchAll();

  context.res = {
    status: 200,
    body: {
      user: user.name,
      diet, keyword, page, pageSize,
      totalCount, totalPages: Math.ceil(totalCount / pageSize),
      recipes: resources
    }
  };
};

10. Challenges & Solutions

# Challenge Impact Solution
1 Blob trigger cold start latency Azure Functions on Consumption plan can take 5-15 seconds for cold starts, delaying data processing. Configured "Always Ready" instances on the Premium plan for the blob trigger function. Added retry logic for transient failures. Cold start now <1s.
2 Redis connection pooling Creating a new Redis connection per request caused connection exhaustion under load. Implemented a singleton connection pattern with redis.createClient() reused across invocations. Added connection health checks and automatic reconnection.
3 OAuth callback URL mismatch Google OAuth returned "redirect_uri_mismatch" errors during development because localhost and deployed URLs differed. Configured multiple redirect URIs in Google Cloud Console. Used environment variables for dynamic callback URL construction. Added staticwebapp.config.json route rules.
4 Cosmos DB query cost (RU/s) Full-text search queries on 7,806 recipes consumed high RU/s, risking throttling (429 errors). Pre-computed search results into Redis. Used Cosmos DB CONTAINS() with partition key targeting. Added indexing policy for recipe_name field. Implemented pagination to limit result set size.
5 JWT token management across tabs Token stored in localStorage was accessible to XSS attacks. Multiple tabs could have stale tokens after logout. Moved token to HttpOnly cookies (inaccessible to JavaScript). Used BroadcastChannel API to synchronize logout across browser tabs. SameSite=Strict prevents CSRF.
6 CSV data quality issues Raw CSV contained duplicate recipes, inconsistent diet type casing ("Keto" vs "keto"), and negative nutritional values. Blob trigger function normalizes all diet types to lowercase, deduplicates by recipe name, validates numeric fields (≥ 0), and logs rejected rows for review.
