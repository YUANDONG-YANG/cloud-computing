阶段 0

装工具、登录

~15 分钟

装 Azure CLI 和 Functions Core Tools

两个都是 deploy.sh 的硬依赖，缺任何一个脚本会在第一步就停下并告诉你装哪个。

# Azure CLI（Ubuntu / Debian）
curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash

# Azure Functions Core Tools v4（需要 Node.js）
npm i -g azure-functions-core-tools@4 --unsafe-perm true

# 验证两个都在
az version --output table
func --version

登录 Azure 并确认用的是哪个订阅

az login
az account show --query "{订阅:name, 订阅ID:id, 用户:user.name}" -o table

如果你有多个订阅（比如学生订阅和公司订阅），确认这里显示的是你想花钱的那个。切换：az account set --subscription "订阅名"。

阶段 1

注册 GitHub OAuth App

~10 分钟

为什么放在部署之前。 回调地址里只需要 Function App 的名字，而那个名字是你自己定的、不是 Azure 分配的。所以先定名字、先注册 OAuth App、把 ID 和 secret 导出成环境变量，deploy.sh 会在部署时自动写进应用设置 —— 省掉「部署完再补设置再重启」那一轮。

定下 Function App 名字，算出回调地址

名字必须在整个 Azure 全局唯一。默认值大概率已经被别人用过，建议直接加个后缀。

# 改成你自己的，只能小写字母、数字和连字符
export FUNCTION_APP=cpsy300-p3-func-yy

echo "回调地址（下一步要一字不差地填）："
echo "https://${FUNCTION_APP}.azurewebsites.net/api/auth/oauth/github/callback"

这个终端别关。 后面所有步骤都依赖这些 export。真关了就把阶段 1 和阶段 2 的 export 重新跑一遍。

在 GitHub 上建 OAuth App

浏览器打开 github.com/settings/developers → OAuth Apps → New OAuth App，四个字段这样填：

字段填什么
Application nameCPSY300 Phase 3
Homepage URL随便填一个能打开的地址，比如你的 GitHub 仓库地址。OAuth 流程不校验它。
Application description留空
Authorization callback URL上一步 echo 出来的那条，一字不差。 多一个斜杠、少一个 /api 都会让 GitHub 返回 redirect_uri_mismatch。

点 Register application，然后在新页面点 Generate a new client secret。

secret 只显示这一次。 现在就复制。而且：不要把它写进仓库里的任何文件 —— 它只能活在环境变量和 Azure 应用设置里。

把 ID 和 secret 导出成环境变量

export GITHUB_CLIENT_ID=粘贴你的_Client_ID
export GITHUB_CLIENT_SECRET=粘贴你的_Client_Secret

# 确认两个都非空（应该输出 ok ok）
echo "${GITHUB_CLIENT_ID:+ok} ${GITHUB_CLIENT_SECRET:+ok}"

Google OAuth 不用做。评分表只要求「至少一个第三方登录」，而 Google 还要额外建 Cloud 项目和同意屏幕。

阶段 2

部署

~15 分钟，大部分在等

设好其余名字并执行

存储账号和 Cosmos 账号的名字也是全局唯一的，同样建议加后缀。存储账号名只能小写字母和数字，不能有连字符。

export STORAGE_ACCOUNT=cpsy300p3stgyy
export COSMOS_ACCOUNT=cpsy300-p3-cosmos-yy
export RESOURCE_GROUP=cpsy300-project3-rg

cd ~/Desktop/claude-computing/Project3
chmod +x deploy.sh teardown.sh
./deploy.sh

应该看到：六个带编号的阶段依次跑完 —— 资源组、存储账号、Cosmos（这步最慢，几分钟）、Function App、前端、上传数据集。结尾打印一个 Deployment Complete! 方框，里面有三个地址：Frontend URL、Function App、Cosmos DB。

把 Frontend URL 抄下来，后面要在浏览器里开它。

如果报名字被占用： 脚本会明确区分「这个名字已经是你的」（重跑而已，继续）和「被别人占了」（它会直接告诉你换名字的命令）。换了名字就重跑 ./deploy.sh，脚本是幂等的。

但注意：如果你改了 FUNCTION_APP，GitHub 那个回调地址也必须跟着改，否则 OAuth 登录会失败。

三个只有真跑才知道的风险点（都没在真实 az 上验证过）：

① Cosmos 容器创建时用 --idx @文件 传索引策略被拒 → 把该行删掉重跑，索引策略会由后端代码在首次运行时补上，不影响功能。

② func ... publish --build remote 不被你装的 Core Tools 版本接受 → 去掉 --build remote 重跑那一条 publish 命令。

③ Cosmos 账号刚建好还在 provisioning 时，az cosmosdb sql container exists 可能返回非零而让脚本致命退出 → 等一两分钟重跑 ./deploy.sh。

阶段 3

验证部署真的成功了

~10 分钟，含等触发器

等 blob 触发器把缓存填好

Consumption 方案上的 blob 触发器是轮询的，不是即时的。上传完到真正跑起来可能要几分钟。

export FUNC_URL=https://${FUNCTION_APP}.azurewebsites.net

# 反复跑这条，直到 recipes_cached 变成 true
curl -s $FUNC_URL/api/health | python3 -m json.tool

应该看到：cache.recipes_cached: true、cache.recipe_count: 7806、cache.insights_cached: true、cache.cosmosdb: "connected"。
security.user_store 应该是 "Cosmos DB"，不是 "in-memory (dev)" —— 后者说明 Cosmos 没连上，用户数据不会持久化。

等太久没动静？ 函数应用缩到零之后轮询才会恢复。先 curl $FUNC_URL/api/health 把它唤醒，再重新上传一次数据集（阶段 5 的命令，但文件用 ../Project1/data/All_Diets.csv）。

确认接口会拒绝匿名调用

这条就是评分表第 9 项（登录才能看 dashboard，10 分）最干净的证据 —— 证明门禁在服务端，不只是前端跳转。

curl -i $FUNC_URL/api/insights

必须看到：HTTP/1.1 401 Unauthorized 和 {"error": "Authentication required. Please log in."}。
如果返回 200 和一堆数据，门禁没生效，别往下走。

在浏览器里注册一个账号并看到图表

打开阶段 2 记下的 Frontend URL。它会把你跳到登录页。切到注册、填一个真能记住的邮箱和至少 8 位的密码。

应该看到：注册完直接进 dashboard，右上角显示你的名字和 Logout 按钮，四张图表有数据，状态条显示数据来自 Cosmos DB，表格有 7,806 条、分页器显示 391 页。

dashboard 一片空白、图表不出来？ 按 F12 开 Network 面板刷新，看 insights 请求打到哪个域名。

打到存储账号域名（…web.core.windows.net/api/…）= config.js 里的占位符没被替换成功，静态网站没有 /api 代理，所以必然 404。重跑 ./deploy.sh 的前端上传那一步。

打到 azurewebsites.net 但报 CORS 错误 = Function App 的 FRONTEND_URL 设置和你实际打开的地址不一致。

接口返回 503？ 说明缓存是空的。这是故意设计的 —— 缓存空的时候宁可报错也不拿假数据冒充，否则触发器坏了和正常工作看起来一模一样。回到上一步等触发器。

证据四：存的是 bcrypt 哈希，不是明文密码

门户：Cosmos DB 账号 → Data Explorer → nutritiondb → users → Items → 点开你刚注册的那条。

截图里要能看清：password_hash 以 $2b$12$ 开头（12 就是 bcrypt 的 cost factor），而且整个文档里没有任何明文密码字段。存成 docs/evidence/bcrypt-hash.png。

阶段 5

准备 v2 缓存演示

~10 分钟

评分表要求演示「清洗和计算只在文件变化时发生」，所以需要两个版本的数据集。data/All_Diets_v2.csv 已经在仓库里了。

用 v2 覆盖同一个 blob 名字

STORAGE_CONN=$(az storage account show-connection-string \
  --name "$STORAGE_ACCOUNT" --resource-group "$RESOURCE_GROUP" \
  --query connectionString -o tsv)

# 先唤醒函数应用，缩到零状态下轮询不会恢复
curl -s $FUNC_URL/api/health > /dev/null

az storage blob upload \
  --container-name raw-data \
  --file data/All_Diets_v2.csv \
  --name All_Diets.csv \
  --connection-string "$STORAGE_CONN" \
  --overwrite true

最容易踩的坑：必须是 --name All_Diets.csv。触发器绑死了 raw-data/All_Diets.csv 这个字面路径，用原文件名 All_Diets_v2.csv 上传，什么都不会触发，你会以为功能坏了。

核对新数字（这些是我在本地跑代码验证过的）

刷新 dashboard，读到的应该正好是下面这些。录视频时要念的「头条数字」是 vegan 的蛋白质 —— 它让蛋白质排名整体反转，vegan 从最后一名变成第一名。
