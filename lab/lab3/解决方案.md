### 0.4 `app.py` 关键结构

```python
from flask import Flask, jsonify, request
import pandas as pd
import json, os, sys

app = Flask(__name__)

# ---------- Subtask 1.1 Preprocessing ----------
df = pd.read_csv("Uber-Jan-Feb-FOIL.csv")
df.dropna(inplace=True)
df.drop_duplicates(inplace=True)
# 讲义的列名是 'Date/Time'；提供的数据集为按天汇总，列名是 'date'
DATE_COL = "Date/Time" if "Date/Time" in df.columns else "date"
df[DATE_COL] = pd.to_datetime(df[DATE_COL])
df["Hour"] = df[DATE_COL].dt.hour
df["Day"] = df[DATE_COL].dt.date
df["DayOfWeek"] = df[DATE_COL].dt.day_name()
df["IsWeekend"] = df["DayOfWeek"].isin(["Saturday", "Sunday"])
# 汇总数据中每行代表多次行程，用 trips 列加权；逐条数据时每行为 1 次
df["Trips"] = df["trips"] if "trips" in df.columns else 1

# ---------- Redis (Subtask 4.1 / 4.2) ----------
redis_client = None
def get_redis():
    global redis_client
    if redis_client is None and os.getenv("REDIS_HOST"):
        import redis
        try:
            client = redis.Redis(
                host=os.getenv("REDIS_HOST"),                  # 本地: localhost / redis
                port=int(os.getenv("REDIS_PORT", "6379")),    # Azure: 6380
                password=os.getenv("REDIS_PASSWORD") or None, # Azure: primary key
                ssl=os.getenv("REDIS_SSL", "false").lower() == "true",
                decode_responses=True,
                socket_connect_timeout=2, socket_timeout=2,
            )
            client.ping()
            redis_client = client
        except Exception as exc:
            app.logger.warning("Redis unavailable: %s", exc)
    return redis_client

# 预计算：按星期几的日均行程（按天汇总后再求均值）
daily_totals = df.groupby("Day")["Trips"].sum()
dow_avg = daily_totals.groupby(pd.to_datetime(daily_totals.index).day_name()).mean()

def predict(ts):
    parsed = pd.to_datetime(ts)
    dow = parsed.day_name()
    actual = daily_totals.get(parsed.date())
    return {
        "timestamp": parsed.isoformat(),
        "day_of_week": dow,
        "predicted_trips": round(float(dow_avg[dow]), 2),
        "actual_trips": int(actual) if actual is not None else None,
        "model": "historical mean daily trips for same day-of-week",
    }

@app.get("/")
def health():
    return jsonify({"status": "ok", "rows": len(df), "cache": "enabled" if get_redis() else "disabled"})

@app.get("/predict_traffic")
def predict_traffic():
    ts = request.args.get("timestamp")
    if not ts:
        return jsonify({"error": "timestamp is required"}), 400
    key = f"predict:{ts}"                      # 讲义要求：以 timestamp 作为 key
    client = get_redis()
    if client:
        try:
            cached = client.get(key)
            if cached:
                return jsonify({**json.loads(cached), "source": "cache"})
        except Exception as exc:
            app.logger.warning("Redis get failed: %s", exc)
    try:
        result = predict(ts)
    except (ValueError, TypeError):
        return jsonify({"error": "invalid timestamp"}), 400
    if client:
        try:
            client.setex(key, 3600, json.dumps(result))   # 过期时间 1 小时
        except Exception as exc:
            app.logger.warning("Redis set failed: %s", exc)
    return jsonify({**result, "source": "computed"})

# ---------- Subtask 1.1 / 1.2 Analysis (python app.py --analyze) ----------
def run_analysis():
    import matplotlib.pyplot as plt
    import seaborn as sns
    print(df.head()); df.info(); print(df.describe(include="all"))
    daily_trips = df.groupby("Day")["Trips"].sum()
    hourly_trips = df.groupby("Hour")["Trips"].sum()
    print("Busiest day:", daily_trips.idxmax(), daily_trips.max())
    print("Peak hour:", hourly_trips.idxmax(), "(dataset is daily aggregate, Hour is always 0)")
    # 柱状图：按天、按小时；热力图：讲义版 + 星期×基地补充版
    ...  # savefig 到 daily_trips.png / hourly_trips.png / heatmap_*.png；有 GUI 时 plt.show()

if __name__ == "__main__":
    if "--analyze" in sys.argv:
        run_analysis()
    else:
        app.run(host="0.0.0.0", port=5000)
```

### 3.2 VMSS + 负载均衡 + 自动扩缩容（5 分）
1. Portal → Virtual machine scale sets → Create
   - 镜像 Ubuntu，规格 B1s（越小越容易压到 70%），初始实例数 1。
   - Scaling：选 Autoscaling，最少 1 台、最多 3 台（受沙盒配额限制）。
   - Networking：新建 **Azure Load Balancer**，负载均衡规则为前端 TCP 5000 → 后端 5000；健康探测使用 HTTP 5000，路径 `/`；NSG 放行 5000。
   - Advanced → Custom data（cloud-init）：
```yaml
#cloud-config
package_update: true
packages: [docker.io]
runcmd:
  - systemctl enable --now docker
  - docker run -d --name uber-app --restart always -p 5000:5000 <dockerhub用户>/uber-app:latest
```
2. 扩缩容规则（Scaling → Custom autoscale）：
   - 扩容：Percentage CPU，平均值 > 70%，时间窗口 5 分钟，实例数 +1，冷却 5 分钟。
   - 缩容：Percentage CPU，平均值 < 30%，时间窗口 5 分钟，实例数 −1，冷却 5 分钟。
3. 验证：`curl http://<LB公网IP>:5000/`；然后运行持续负载的 JMeter 计划（**此时不启用 Redis**，作为"缓存前"的基线），并记录开始和结束时间。
4. 如果 CPU 始终达不到 70%：增加线程数，或在多台机器上同时运行 JMeter；也可以给接口加一个只在压测时使用的 `?work=N` 参数，制造可控的 CPU 开销，并在报告中如实说明。

## Task 4：Redis 缓存（10 分）

### 4.1 本地 Redis（5 分）
推荐做法（app 和 Redis 位于同一个 Docker 网络）：
```bash
docker network create uber-net
docker run -d --name redis --network uber-net -p 6379:6379 redis
docker run -d --name uber-app --network uber-net -p 5000:5000 -e REDIS_HOST=redis uber-app
curl "localhost:5000/predict_traffic?timestamp=2/20/2015"   # "source":"computed"
curl "localhost:5000/predict_traffic?timestamp=2/20/2015"   # "source":"cache"
docker exec -it redis redis-cli KEYS 'predict:*'
docker exec -it redis redis-cli TTL 'predict:2/20/2015'     # 约 3600，证明设置了 1 小时过期
```
（也可以使用 `docker compose up`，把 compose 文件中的环境变量改为 `REDIS_HOST: redis`。）

**截图**
- [ ] redis-cli 输出：`KEYS` 列出 `predict:2/20/2015` 等 key，以及 TTL
- [ ] 两次调用的输出放在同一张截图里：第一次为 `computed`，第二次为 `cache`

### 4.2 Azure Cache for Redis（5 分）
1. Portal → Azure Cache for Redis → Create：与 VM **同一资源组、同一区域**，Basic C0，设置唯一的 DNS 名称。
   - 如果 Basic C0 在当前订阅中无法创建，截图记录报错，改用 Azure Managed Redis 最小规格，并在报告中说明。
2. 部署完成后，在 Authentication / Access keys 中确认访问密钥认证已启用，复制主机名、6380 端口和主密钥（**不要截到密钥本身**）。
3. 在 3.1 的 VM 上重启 app：
```bash
cat > ~/redis.env <<'EOF'
REDIS_HOST=<名称>.redis.cache.windows.net
REDIS_PORT=6380
REDIS_SSL=true
REDIS_PASSWORD=<主密钥>
EOF
chmod 600 ~/redis.env
sudo docker rm -f uber-app
sudo docker pull <dockerhub用户>/uber-app:latest
sudo docker run -d --name uber-app --restart unless-stopped -p 5000:5000 --env-file ~/redis.env <dockerhub用户>/uber-app:latest
curl http://localhost:5000/                     # "cache":"enabled"
curl "http://<VM公网IP>:5000/predict_traffic?timestamp=2/14/2015"   # computed
curl "http://<VM公网IP>:5000/predict_traffic?timestamp=2/14/2015"   # cache
```
4. 对 VMSS 做同样的修改：更新 cloud-init，把 env 参数加到 `docker run` 中，然后对实例执行 Upgrade 或 Reimage。启用缓存后，再跑一次同样的持续负载 JMeter 计划，作为"缓存后"的数据。

## Task 5：监控与清理（10 分）

### 5.1 性能对比（5 分）
数据来源与做法：

| 指标 | 来源 | 做法 |
|---|---|---|
| CPU 使用率 | Azure Monitor → VMSS → Metrics → Percentage CPU（平均值，可按实例拆分） | 用时间筛选器分别选"缓存前"和"缓存后"两段压测时间，各截一张；或者在一张图中用注释标出分界点 |
| 扩缩容动作 | Monitor → Autoscale → Run history；Activity log 中的 "Autoscale scale up/down" 事件；Instance count 指标 | 比较两段时间内的扩容次数 |
| 响应时间 | VM 内置指标没有这一项。**方案 A（推荐，成本最低）**：两次 JMeter 结果（`report_nocache/` 与 `report_cache/` 的 HTML 报告，或 Summary Report）。**方案 B**：接入 Application Insights，在 Azure Monitor 中查看 Server response time | 在报告中把两张截图并排放，写明标签 |

**截图**
- [ ] CPU 图：标注 "Before caching / After caching"
- [ ] 扩缩容动作（Run history 或 Instance count 图）：标注前后
- [ ] 响应时间对比（JMeter 或 Application Insights）：标注前后

**结论写法**：如实给出数字。如果响应时间的改善不明显，要解释原因：数据集只有 354 行，计算成本本身很低，而远程 Redis 使用 TLS，每次请求要多一次网络往返；缓存的主要收益体现在 CPU 降低和扩容次数减少上。
