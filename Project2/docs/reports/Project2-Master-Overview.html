2. Cloud Architecture

The application follows a serverless architecture pattern with three main Azure services working together. The user accesses the Static Web App, which calls the Azure Function API, which reads data from Azure Blob Storage.

+-----------------------------------+ | Azure Cloud | | (Resource Group: | | cpsy300-nutritional-rg) | | | +----------+ | +--------------------------+ | | | HTTPS | | Azure Static Web App | | | User / |--------->| | (nutritional-dashboard) | | | Browser | | | - HTML / CSS / JS | | | |<---------| | - Charts (Chart.js) | | +----------+ | +-----------+--------------+ | | | | | fetch("/api/...") | | | | | +-----------v--------------+ | | | Azure Function App | | | | (nutritional-func-app) | | | | - Python 3.10+ | | | | - HTTP Trigger | | | | - Pandas, data clean | | | +-----------+--------------+ | | | | | BlobServiceClient | | | | | +-----------v--------------+ | | | Azure Blob Storage | | | | (nutritionalstorage) | | | | - Container: data | | | | - All_Diets.csv | | | | (7,806 rows) | | | +--------------------------+ | | | +-----------------------------------+ +-------------------+ | GitHub Actions |----> Deploy Function App | CI/CD Pipeline |----> Deploy Static Web App +-------------------+

Architecture Components

Static Web AppHosts the dashboard frontend. Serves HTML, CSS, and JavaScript. Renders 4 chart types using Chart.js/inline SVG.
Function AppServerless HTTP-triggered Python function. Reads CSV from Blob Storage, cleans data with Pandas, returns JSON.
Blob StorageStores All_Diets.csv (7,806 recipes). Accessed via BlobServiceClient using connection string from environment variables.
GitHub ActionsCI/CD pipeline deploys both the Function App and the Static Web App on every push to main.

Azure Blob Storage Setup

A general-purpose v2 storage account is created to host the All_Diets.csv dataset. The CSV is uploaded to a blob container named data.

# Create storage account
az storage account create \
  --name nutritionalstorage \
  --resource-group cpsy300-nutritional-rg \
  --location canadacentral \
  --sku Standard_LRS

# Create container
az storage container create \
  --name data \
  --account-name nutritionalstorage

# Upload dataset
az storage blob upload \
  --account-name nutritionalstorage \
  --container-name data \
  --name All_Diets.csv \
  --file ./All_Diets.csv

3.3 Function App

Azure Function App Deployment

A Python-based Function App with an HTTP trigger is deployed. It reads the CSV from Blob Storage, performs data cleaning, and returns aggregated nutritional insights as JSON.

# Create Function App
az functionapp create \
  --name nutritional-func-app \
  --resource-group cpsy300-nutritional-rg \
  --storage-account nutritionalstorage \
  --consumption-plan-location canadacentral \
  --runtime python \
  --runtime-version 3.10 \
  --functions-version 4 \
  --os-type Linux

# Set environment variable for storage connection
az functionapp config appsettings set \
  --name nutritional-func-app \
  --resource-group cpsy300-nutritional-rg \
  --settings AzureWebJobsStorage="<connection-string>"

# Deploy function code
func azure functionapp publish nutritional-func-app

5. Key Code Sections

5.1 Azure Function — HTTP Trigger (Python)

The main serverless function reads All_Diets.csv from Azure Blob Storage, performs data cleaning with Pandas, and returns aggregated nutritional insights as JSON.

import azure.functions as func
import pandas as pd
import json
import os
from azure.storage.blob import BlobServiceClient

def main(req: func.HttpRequest) -> func.HttpResponse:
    try:
        # Connect to Azure Blob Storage
        connect_str = os.environ["AzureWebJobsStorage"]
        blob_service = BlobServiceClient.from_connection_string(connect_str)
        container = blob_service.get_container_client("data")
        blob = container.get_blob_client("All_Diets.csv")

        # Download and parse CSV
        csv_data = blob.download_blob().readall().decode("utf-8")
        from io import StringIO
        df = pd.read_csv(StringIO(csv_data))

        # Data cleaning
        df.columns = df.columns.str.strip().str.lower()
        numeric_cols = ["protein(g)", "carbs(g)", "fat(g)"]
        df[numeric_cols] = df[numeric_cols].apply(pd.to_numeric, errors="coerce")
        df.dropna(subset=numeric_cols, inplace=True)

        # Aggregate by diet type
        diet_param = req.params.get("diet", None)
        if diet_param:
            df = df[df["diet_type"].str.lower() == diet_param.lower()]

        summary = df.groupby("diet_type")[numeric_cols].agg(["mean", "sum", "count"])
        result = summary.to_dict()

        return func.HttpResponse(
            json.dumps(result, indent=2),
            mimetype="application/json",
            status_code=200
        )
    except Exception as e:
        return func.HttpResponse(
            json.dumps({"error": str(e)}),
            mimetype="application/json",
            status_code=500
        )

5.2 Frontend Fetch Code (JavaScript)

The dashboard frontend fetches data from the Azure Function endpoint and renders it into charts.

// Configuration
const API_BASE = "https://nutritional-func-app.azurewebsites.net/api";

// Fetch nutritional insights
async function fetchNutritionalData(dietType = null) {
    const url = dietType
        ? `${API_BASE}/nutritional-insights?diet=${dietType}`
        : `${API_BASE}/nutritional-insights`;

    try {
        const response = await fetch(url, {
            method: "GET",
            headers: { "Content-Type": "application/json" }
        });

        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const data = await response.json();
        return data;
    } catch (error) {
        console.error("API fetch failed:", error);
        showErrorToast("Failed to load data. Please try again.");
        return null;
    }
}

// Render bar chart with fetched data
async function renderBarChart() {
    const data = await fetchNutritionalData();
    if (!data) return;

    const ctx = document.getElementById("barChart").getContext("2d");
    new Chart(ctx, {
        type: "bar",
        data: {
            labels: Object.keys(data),
            datasets: [
                { label: "Protein (g)", data: extractMeans(data, "protein(g)") },
                { label: "Carbs (g)",   data: extractMeans(data, "carbs(g)") },
                { label: "Fat (g)",     data: extractMeans(data, "fat(g)") }
            ]
        },
        options: { responsive: true, plugins: { title: { display: true } } }
    });
}

// Filter handler
document.getElementById("dietFilter").addEventListener("change", async (e) => {
    const diet = e.target.value === "all" ? null : e.target.value;
    const data = await fetchNutritionalData(diet);
    updateAllCharts(data);
});

8. Challenges & Solutions

#ChallengeSolutionOutcome
1 CORS blocking frontend requests
Browser refused cross-origin fetch() calls from Static Web App to Function App.		 Added the Static Web App domain to the Function App's CORS allowed-origins list via az functionapp cors add. Ensured no trailing slash in the origin URL. Frontend can call API without browser security errors. Solved
2 Azurite to Azure Storage migration
Connection strings and endpoint formats differ between local Azurite and real Azure Blob Storage.		 Used environment variables (AzureWebJobsStorage) so the same code works in both environments. Updated the connection string in Azure Portal app settings. Seamless transition with zero code changes to the function logic. Solved
3 Cold start latency
Azure Functions on Consumption plan had 5-10 second cold starts, causing slow first loads of the dashboard.		 Added loading spinners to the frontend. Considered pre-warming strategies. Documented the trade-off between Consumption (cheap) and Premium (fast) plans. User sees loading indicator instead of empty/broken charts. Acceptable for course project scope. Solved
4 CSV encoding issues
Some recipe names contained special characters that caused parsing errors when reading from Blob Storage.		 Explicitly decoded blob content as UTF-8 (blob.download_blob().readall().decode("utf-8")) and added errors="coerce" to numeric conversions in Pandas. All 7,806 recipes parsed correctly without data loss. Solved
5 Large JSON response size
Returning all 7,806 recipes in a single response was slow and caused browser lag when rendering.		 Implemented server-side pagination (?page=1&limit=20) and returned only aggregated summaries for chart endpoints. Frontend fetches pages on demand. Fast initial load. Users can browse individual recipes via pagination controls. Solved
6 GitHub Actions deployment configuration
CI/CD workflow needed separate deployment steps for the Function App and the Static Web App.		 Created a multi-job workflow: one job deploys the Function App using azure/functions-action, another deploys the Static Web App using Azure/static-web-apps-deploy. Both triggered on push to main. Automated deployment pipeline. Code pushes trigger build and deploy for both services. Solved
